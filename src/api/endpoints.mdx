# Endpoints

The API is written as an HTTP JSON REST API. Meaning all requests are expected to be of `Content-Type: application/json`, and will return JSON. Also, will use the standard [HTTP REST status codes](https://www.restapitutorial.com/httpstatuscodes.html).

All Api Endpoints require the API key within the `config.json` to make / return responses to requests.

The API Key can be provided in 3 ways:

- Through an `Authorization` Header.

`Authorization: my-api-key`

- Through the `api_key` query paramater

`localhost:3000/stream?api_key=my-api-key`

- Through the `api_key` POST body

```
{

"api_key": "my-api-key"

...

}
```

## GET /stream

### Description

Returns the status of the stream.

### Query Params

None

### Example Successful Response:

```
{
    "isRunning": true
}
```

## POST /stream/start

### Description

Starts the stream, if not already running.

### Body Params

None

### Example Successful Response:

```
{
    "message": "OK"
}
```

## POST /stream/stop

### Description

Stops the stream, if running.

### Body Params

None

### Example Successful Response:

```
{
  "message": "OK"
}
```

## POST /stream/restart

### Description

Restarts the stream, if running will stop and then start, if not running will simply start.

### Body Params

None

### Example Successful Response:

```
{
  "message": "OK"
}
```

## GET /config

### Description

Returns a param of the config.json. If no key is set, all config params will be returned

### Query Params

- `key` - The config key in dot-notation (example: 'api.host', 'interlude.overlay.enabled')

### Example Response:

**HTTP 200** - Successful

```
{
    "key": "interlude.enabled",
    "value": true
}
```

**HTTP 404** - Key not existant

```
{
    "key": "interlude.awesomeness_level",
    "value": null
}
```

## POST /config

### Description

Changes a config param in the config.json. If they key has no value, it will be added

### Body Params

- `key` - The config key in dot-notation (example: 'api.host', 'interlude.overlay.enabled')
- `value` - The new value for the config in json (example: (string) "test", (number) 5, (boolean) true)

### Example Response:

**HTTP 200** - Successful

```
{
    "response": {
        "key": "interlude.frequency",
        "oldValue": "0.5",
        "newValue": "0.2"
    }
}
```

**HTTP 200** - Key not existant, new key will be saved

```
{
    "response": {
        "key": "interlude.awesomeness_level",
        "newValue": "over 9000"
    }
}
```

**HTTP 400** - `value` is not JSON, the key is not valid (e.g. `__proto__`), or the change would leave a config the stream can't run

## PUT /config

### Description

Replaces the whole config.json. The previous file is kept as `config.json.bak`. Used by the web console's config editor.

### Body Params

- `config` - The complete new config, as a JSON object. It must keep its `api` section, and a `radio` section (and `interlude`, when enabled) with `audio_directory` and `video_directory`.

### Example Response:

**HTTP 200** - Successful

```
{
    "message": "OK",
    "backup": "config.json.bak"
}
```

**HTTP 400** - Not an object, or missing one of the sections above

## GET /stream/status

### Description

Detailed stream status: whether it is running, the item currently playing (same shape as a history item), and ffmpeg's progress through it. `progress.seconds` includes the 3 second lead-in silence.

### Example Successful Response:

```
{
    "isRunning": true,
    "nowPlaying": {
        "type": "radio",
        "audio": { "path": "...", "duration": 3512.4, "metadata": { "title": "...", "artist": "..." } },
        "video": { "path": "..." },
        "date": 1790000000000
    },
    "progress": { "seconds": 612, "fps": 25, "kbps": 2630.1, "date": 1790000612000 },
    "uptime": 86400
}
```

## GET /stream/log

### Description

Returns up to the last 500 lines of console output, with color codes removed.

### Query Params

- `since` - (optional) Only return lines with an `id` greater than this.

### Example Successful Response:

```
{
    "log": [
        { "id": 41, "date": 1790000000000, "text": "Playing the audio:" }
    ]
}
```

## GET /console

### Description

The web console: a page for remotely controlling the stream (start / stop / skip), watching what is playing and the log, editing the config and browsing the library. Open `http://<api host>:<api port>/console` in a browser and sign in with a console user, or with the `api.key`.

Add a console user (or change their password) on the machine running the stream:

```
podcast-radio --set-password [Project Name/Directory]
```

This stores the username and a hashed password in `console.users` in the config.json. Signed in sessions last `console.session_hours` (default 12) and end when the stream process restarts. After 5 wrong passwords from one address, logins from it are refused for 15 minutes.

Once a console user exists, an empty `api.key` no longer leaves the api open: requests need a signed in session (or the key, if one is set).

The console is disabled unless `api.key` is set or a console user exists. Credentials are sent with every request, so only expose the console over HTTPS (for example behind nginx) or an SSH tunnel, never plain HTTP on the open internet.

## POST /console/login

### Description

Signs in a web console user. Does not need the api key.

### Body Params

- `username`
- `password`

### Example Response:

**HTTP 200** - Successful. Send the token as `Authorization: Session <token>` on other requests.

```
{
    "token": "3f9a...",
    "username": "dcr",
    "expires": 1790043200000
}
```

**HTTP 401** - Wrong username or password
**HTTP 429** - Too many failed logins from this address

## POST /console/logout

### Description

Ends the session passed as `Authorization: Session <token>`.

## GET /stream/queue

### Description

The tracks queued to play next, in order. When the queue is empty the stream picks tracks at random.

### Example Successful Response:

```
{
    "queue": [
        { "path": "/home/me/my-radio/audio/episode-12.mp3", "date": 1790000000000 }
    ]
}
```

## POST /stream/queue

### Description

Queues a track. Only files listed by `GET /library/audio` can be queued. Queued tracks skip interludes, and are marked `"requested": true` in the history.

### Body Params

- `path` - A path exactly as returned by `GET /library/audio`
- `play_next` - (optional) `true` to put it at the front of the queue
- `play_now` - (optional) `true` to put it at the front and skip to it straight away

### Example Response:

**HTTP 200** - The updated queue, as for `GET /stream/queue`
**HTTP 400** - The track isn't in the library, or the queue is full (200 tracks)

## POST /stream/queue/remove

### Body Params

- `index` - Position in the queue, from 0
- `path` - (optional) Only remove it if this is still the track at `index`, otherwise **HTTP 409**

## POST /stream/queue/clear

### Description

Empties the queue.

## GET /podcasts

### Description

The podcast feeds episodes are downloaded from, and how the downloading is going. `download` is set while an episode downloads, `nextCheck` while waiting for the next check.

### Example Successful Response:

```
{
    "checking": false,
    "lastCheck": "2026-09-30T16:00:00.000Z",
    "nextCheck": "2026-09-30T17:00:00.000Z",
    "checkEveryMinutes": 60,
    "feeds": [
        {
            "url": "https://example.com/feed.xml",
            "title": "My Show",
            "directory": "./audio/My Show",
            "keepLatest": 10,
            "lastChecked": "2026-09-30T16:00:00.000Z",
            "episodes": 10,
            "latest": "Episode 120: ..."
        }
    ]
}
```

## POST /podcasts/check

### Description

Checks the feeds now instead of waiting for the next check. Returns straight away, with the same response as `GET /podcasts`.

## POST /podcasts/feeds

### Description

Adds a feed to `config.json`, after reading it to check it works. Its episodes go into a folder named after the show, inside `radio.audio_directory`, and downloading starts straight away. Not available when the project uses `config.js`.

### Body Params

- `url` - The feed's url, starting with `http://` or `https://`.
- `keep_latest` - Optional. How many of the newest episodes to keep (default 10). 0 keeps every episode.

### Example Response:

**HTTP 200** - Added

```
{
    "feed": { "title": "My Show", "episodesInFeed": 120, "url": "https://example.com/feed.xml", "keep_latest": 10, "directory": "./audio/My Show" }
}
```

**HTTP 400** - Not a url, already added, not a readable RSS feed, or no audio episodes

## POST /podcasts/feeds/remove

### Description

Removes a feed from `config.json`. Episodes already downloaded stay; delete the show's folder to remove them.

### Body Params

- `url` - The feed's url.

**HTTP 404** - That feed isn't in the config
